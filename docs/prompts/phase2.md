## 一、目标

某个分块完成后，空闲出来的连接从"预计剩余时间最长"的分块那里，把它剩余区间的后半段分过来，用一个新连接继续下载。同时下载的连接数始终不超过配置的连接数。总长未知的顺序下载不做切分。

## 二、写入 ARCHITECTURE.md（原样追加为第 10 节）

```
## 10. 动态切分协议（Phase 2 确立）

### 10.1 每个分块的共享状态（一个小的 std Mutex 保护，持锁期间不做任何 IO 和 .await）
- reserved：已"预留"的位置。分块每次写入前，在锁内先预留，再在锁外执行写入
- end：当前的区间终点（可以被缩小）

### 10.2 分块写入（被切分方）
1. 加锁：读取 end；本次可写长度 = min(数据长度, end - reserved)；reserved 增加该长度；解锁
2. 可写长度为 0 → 说明区间已被缩小到当前位置，丢弃剩余数据，主动关闭连接，分块以"完成"结束
3. 只写入可写长度部分（超出 end 的数据截掉丢弃）
4. 写入失败需要重试时：加锁，把 reserved 退回到 acked，解锁，然后按 1d 的规则从 acked 重试

### 10.3 切分（窃取方）
1. 选择被切分的分块：在所有正在下载的分块中，选预计剩余时间（剩余字节 / 最近速度）最长的；速度为 0（例如正在退避重试）的视为无穷大，优先选中
2. 加锁读取该分块的 reserved 和 end，计算切分点：split = reserved + (end - reserved) / 2，向下对齐到 64 KiB
3. 只有切分后两段都不小于最小切分大小（默认 1 MiB），才允许切分；否则放弃本次切分
4. 加锁：再次确认 reserved < split（被切分方可能在此期间又前进了）；不满足则放弃；满足则把 end 改为 split；解锁
5. 数据库（有 ctx 时）：在一个事务中，把被切分分块的 end 改为 split，并插入新分块 [split, 原 end)，committed = split。**这个事务提交成功后**，才能为新分块发起网络请求
6. pool.shrink_end(被切分分块, split)：由于第 4 步已经保证 reserved ≤ split，这一步必定成功；如果失败，属于程序错误，任务失败
7. allocate_chunk(split, 原 end) → register → 用新连接下载

### 10.4 不变式
- 任何时刻，所有分块的 [start, end) 区间互不重叠，并且拼起来正好覆盖 [0, total)。数据库中的分块记录同样满足这一点
- 每个分块的 committed ≤ acked ≤ reserved ≤ end
- 检查点只为已写入数据库的分块写入 committed
```

## 三、实现要求

1. 每个分块记录最近一段时间的速度，用于计算预计剩余时间（建议用最近 3 到 5 秒的滑动窗口）
2. 新增配置：`min_split_size`（默认 1 MiB）；`dynamic_split`（默认开启）。CLI 新增 `--no-split`，用于关闭切分、与静态分块做对比
3. 进度快照和 CLI 汇总表中，每个分块新增"来源"一列：初始分块，或"从第几号分块切出"；任务汇总新增切分次数
4. 续传时，读取数据库中的全部分块记录（包括切分出来的分块），对每个 committed < end 的分块继续下载；续传过程中同样允许切分
5. 每次切分输出一条 info 日志，字段包括：被切分分块、切分点、新分块编号、被切分分块的速度和预计剩余时间

## 四、测试（本地测试服务器，按需新增服务器能力）

**正确性**
1. 单元测试：切分点计算（64 KiB 对齐、两段都不小于最小切分大小、剩余太小时放弃）
2. 单元测试：10.2 的写入截断——end 被缩小后，跨越 end 的数据只写入到 end 为止，分块以"完成"结束
3. 单元测试：第 10.3 节第 4 步的竞争——被切分方在此期间前进到超过 split，切分被放弃，没有任何数据丢失
4. 服务器对第 0 号分块的请求限速到很慢（例如 50 KiB/s），其他请求不限速：开启切分时，总耗时远短于关闭切分（`--no-split`）时，第 0 号分块被切分至少一次，最终文件逐字节正确。报告两种方式的实测耗时
5. 并发压力：服务器对每个请求随机分配速度（种子可控），8 个连接、64 MiB 文件，运行 50 个不同种子。每次都满足：文件逐字节正确；下载结束时数据库中的分块区间互不重叠，并且正好覆盖整个文件
6. 切分与重试同时发生：被切分的分块在切分前后中途断开并重试，文件仍然逐字节正确
7. 切分与取消同时发生：在切分过程中取消，结果为 Cancelled，数据库分块记录满足不变式，之后 resume 能完成并逐字节正确
8. 续传：下载到一半暂停时，数据库中已经有切分出来的分块，执行 resume，完成且逐字节正确
9. 切分与限速：总速度不超过限速值的 120%
10. 连接数上限：任何时刻同时在下载的分块数，都不超过配置的连接数（在测试服务器端统计并发请求数，取最大值断言）
