## 第 0 步：核实 queue pause 的竞态
v0.1.1 的 queue pause 直接修改数据库中排队任务的状态。担心的情况：运行器已经把该任务读入内存队列、尚未开始下载，CLI 把数据库改为暂停后，运行器仍按内存中的记录开始下载。
1. 写测试 pause_queued_while_runner_running：运行器在运行，同时下载任务数设为 1；先入队一个慢速大任务 A 占住唯一名额，再入队任务 B；等待 2 秒（确保运行器已读取 B）；用 CLI 暂停 B；然后让 A 完成或取消；断言 B 在之后 10 秒内始终没有开始下载（状态保持 Paused，没有 .idm-part 文件）
2. 运行它。如果通过，记录结论，说明运行器开始下载前会重新核对数据库状态（给出代码位置）；如果失败，停下报告，附修复方案，不要修改

1. build-release.ps1 增加：确认 dist/idm-rs-firefox-0.1.0-signed.xpi 存在，且 SHA256 为 D918224C3DF5800289A8311245D555A4328053C2B8AD980CDD229729C60F3227（不存在或不一致即失败退出）；把它作为资源随安装包安装到安装目录下，安装后的文件名为 idm-rs-firefox.xpi，并给出它在安装目录中的实际相对路径

## 第 2 步：检测 Firefox 与扩展状态（idm-core 或桌面服务层，纯函数优先）
1. 查找 Firefox：依次读取注册表 HKLM 与 HKCU 下的 Software\Microsoft\Windows\CurrentVersion\App Paths\firefox.exe 的默认值；都没有则检查 %ProgramFiles%\Mozilla Firefox\firefox.exe 与 %ProgramFiles(x86)%\Mozilla Firefox\firefox.exe。返回找到的路径或"未安装"
2. 检测扩展是否已安装：读取 %APPDATA%\Mozilla\Firefox\profiles.ini，解析出全部配置文件夹（同时支持相对路径与绝对路径两种写法），检查各配置文件夹下 extensions\idm-rs@local.xpi 是否存在。返回：已安装（列出配置名）、未安装、无法判断（profiles.ini 不存在等）
3. 解析 profiles.ini 的逻辑写成纯函数，接收文件内容与基础目录，返回配置文件夹路径列表
4. 只读，不写任何 Firefox 文件
