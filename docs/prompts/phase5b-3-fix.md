## 第 1 步：详情面板高度
用户反馈：详情面板固定 200px，下方大片空白，连接表却出现滚动条。改为：
1. 主区域右侧（任务表格 + 详情面板）改为纵向弹性布局，占满分类栏右侧的全部可用高度
2. 详情面板默认高度按内容自动计算：标题行 + 分段进度条 + 连接表全部行，刚好放下不出滚动条
3. 自动高度的上限：保证任务表格至少保留 5 行（表头加 5 行数据）的高度；超出上限时才在连接表内部出现滚动条
4. 任务表格与详情面板之间加一条可拖动的水平分隔线（高约 5px，鼠标悬停显示上下拖动光标）。拖动后改为用户指定的高度，同样受第 3 条的上下限约束（详情面板最小 120px）
5. 用户拖动过的高度保存在 localStorage（键名 idm-rs.detailHeight），下次启动沿用；读取失败或数值异常时回到自动高度。localStorage 的读写都用 try/catch 包住
6. 窗口大小改变时重新计算上限，不能让表格或面板被挤出可视区
7. 面板折叠时，任务表格占满全部高度

## 第 2 步：每个连接的速度（前端计算）
后端 task_detail 返回的 speed_bps 目前为 0。改为前端计算：
1. 每次 500ms 刷新时，按"分块编号 + 起始位置"作为键，记录该分块的 downloaded 和时间戳
2. 速度 = 最近约 2 秒内的下载增量 ÷ 经过的时间（保留最近几次采样做滑动平均，让数字平稳）
3. 分块状态不是"下载中"时速度显示"—"；增量为负（分块被拆分导致范围变化）时丢弃该分块的历史重新计算
4. 选中的任务变化或面板关闭时清空所有采样记录
5. 后端 speed_bps 大于 0 时优先使用后端的值（为以后后端补上真实速度预留）
